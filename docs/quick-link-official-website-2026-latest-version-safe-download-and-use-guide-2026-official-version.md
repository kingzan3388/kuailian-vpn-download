## 二、核心概念

### 2.1 概念定义

在讨论快连之前，有必要厘清几个关键概念。**网络代理（Proxy）** 是一种中间服务器，充当用户设备与互联网资源之间的桥梁。当用户通过代理访问网络时，请求首先发送至代理服务器，再由代理服务器转发至目标网站。这种方式可以隐藏用户的真实IP地址，从而实现匿名访问。而 **VPN（虚拟专用网络，Virtual Private Network）** 则是一种更为高级的代理技术，它通过在用户设备与目标服务器之间建立一个加密的隧道，确保所有通过该隧道传输的数据都无法被第三方窃听或篡改。

快连本质上是一种基于 **Shadowsocks** 或 **V2Ray** 等现代代理协议改良的VPN服务。与传统的PPTP或L2TP VPN不同，快连采用了更轻量级、更难以被检测的协议栈。其核心优势在于**混淆（Obfuscation）** 与**多路复用（Multiplexing）** 技术。混淆技术将代理流量伪装成普通的HTTPS网页流量，使其在网络审查系统中难以被识别和拦截；而多路复用则允许单个TCP连接同时承载多个数据流，显著降低了连接建立的开销，提升了在高延迟网络环境下的传输效率。

### 2.2 工作原理

快连的工作原理可以分解为以下几个关键步骤：

1.  **客户端初始化**：用户在设备上安装快连客户端后，客户端会生成一个唯一的本地代理端口（通常是1080或7890）。同时，客户端会从快连服务器获取一组可用的节点列表，这些节点分布在不同的地理区域，每个节点都由一个IP地址、端口号、加密密码和传输协议组成。

2.  **连接建立**：当用户启用快连时，客户端会选择一个最优节点（基于延迟、丢包率和负载情况）。随后，客户端通过**TLS 1.3**或**WebSocket**协议向该节点发起连接请求。这个过程与访问一个普通的HTTPS网站无异，因此很难被深度包检测（DPI）设备识别为代理流量。

3.  **数据封装与加密**：一旦连接建立，所有来自用户设备的网络数据包（例如HTTP请求、DNS查询、WebSocket帧）都会被客户端拦截。客户端使用预共享的密钥（通过AES-256-GCM或ChaCha20-Poly1305等强加密算法）对这些数据进行加密。加密后的数据被封装成标准的TCP或UDP数据包，并通过之前建立的加密隧道发送至快连服务器。

4.  **数据转发与解密**：快连服务器接收到加密数据包后，使用相同的密钥进行解密，恢复出原始的网络请求。然后，服务器以自身的IP地址作为源地址，向目标网站（例如Google、YouTube或Twitter）发起请求。目标网站返回的响应数据同样被服务器加密，并通过隧道回传给客户端。

5.  **本地代理处理**：客户端接收到加密的响应数据后，进行解密，并通过本地代理端口将数据转发给用户设备上的应用程序（如浏览器或即时通讯软件）。整个过程中，用户设备上的应用程序无需任何特殊配置，只需将网络代理设置为本地地址（127.0.0.1）和客户端指定的端口即可。

这种设计确保了用户的所有网络活动都得到了端到端的加密保护，且用户的真实IP地址在目标网站看来始终是快连服务器的IP，从而实现了真正的匿名访问。

对于追求极致性能或特定需求的用户，快连2026版提供了以下高级功能：

    -   **原理**：允许您指定哪些应用程序的流量通过代理，哪些直接连接互联网。这可以避免国内视频网站（如B站）因走代理而导致的限速，同时确保国际应用（如WhatsApp）的访问。

2.  **自定义路由规则（PAC模式）**：
    -   **原理**：使用Proxy Auto-Config（PAC）文件，根据访问的域名自动决定是否使用代理。这比全局模式更智能，能有效减少不必要的流量消耗。
    -   **操作**：在“代理模式”中选择“PAC模式”。高级用户可以编写或导入自定义的PAC脚本。例如，一个简单的PAC规则如下：
        ```javascript
        function FindProxyForURL(url, host) {
            // 所有以 .google.com 结尾的域名走代理
            if (shExpMatch(host, "*.google.com")) {
                return "PROXY 127.0.0.1:1080";
            }
            // 其他域名直连
            return "DIRECT";
        }
        ```

3.  **多路复用与UDP转发**：
    -   **原理**：开启多路复用（mux）可以减少TCP握手次数，显著提升网页加载速度。UDP转发则允许您使用需要UDP协议的应用，如网络游戏或语音通话。

4.  **TLS指纹混淆**：
    -   **原理**：针对深度包检测（DPI）设备，通过模拟不同浏览器或客户端的TLS握手特征，使代理流量更难被识别。
    -   **操作**：在“传输设置”中，选择“TLS”协议，并设置“指纹”为“Chrome”或“Safari”。这能有效对抗部分网络运营商的精确识别。
